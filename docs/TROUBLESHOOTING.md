# AudioWire troubleshooting

## The phone cannot find the PC

Run AudioWire on Windows, connect both devices to the same local network, and permit Local Network access in iPhone Settings. Guest Wi-Fi and wireless client isolation often prevent devices talking to each other. Try the address and port displayed by the PC app instead of discovery.

The installer creates app-specific inbound TCP/UDP rules for Private networks and the local subnet. A portable build has not installed those rules. Windows Firewall may prompt on first launch. Use a trusted Private network; do not disable the firewall.

A QR generated by the PC can be scanned with the iPhone Camera app; opening its AudioWire link selects the address and supplies the code. The code expires after two minutes. No online QR service is involved.

## Pairing fails

Enter the current six digits, including leading zeroes. After five exchanges, or after two minutes, click **Pair a new phone** on the PC. If an already paired device reports that its identity changed, forget the saved device and pair again.

An active PC accepts only one phone. Disconnect the current phone before connecting another.

## PC sound still plays on the PC

Without the AudioWire driver, speaker mode captures the normal Windows output. That output still plays locally. With a validated driver installed, select **AudioWire Speaker** in the desired application's audio settings, or explicitly enable **Use iPhone for all PC sound**.

## A call app cannot use the iPhone microphone

A normal Windows input device requires the AudioWire kernel driver. Source code or the Windows executable alone does not install one. Install only a validated signed package, or use an isolated developer VM for a test-signed candidate. Managed PC policy may block installation.

If the phone's microphone permission was declined, enable it in iPhone Settings and select microphone or speakerphone mode again.

## Audio breaks up

Prefer a strong 5 GHz network. Start with Balanced quality. Increase the latency/stability reserve in Settings if needed; zero means automatic. Max quality sends PCM and needs more bandwidth. Low-power or hot iPhones use the voice preset.

The diagnostics latency is control-channel round-trip time. It does not include the audio pipeline or the speaker-to-microphone path and must not be used to claim the product's acoustic latency target.

## Sound settings do not restore

AudioWire journals previous device selections before changing them and recovers unfinished selections on normal startup after a force-kill. Automatic restoration applies only to devices that AudioWire actually selected. It preserves a different device selected manually by the user. The convenience toggle uses Windows' undocumented PolicyConfig interface; if Windows rejects it, open Sound settings and select the previous speakers/microphone manually.

## Development validation

A simulator cannot prove iPhone echo cancellation. An app test cannot prove a driver is safe. Follow the driver VM test matrix and the physical-device release checks in `docs/IMPLEMENTATION.md`. Copy diagnostics rather than supplying pairing codes, keys or private recordings.
